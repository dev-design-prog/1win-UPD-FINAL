# Что изменилось (v20)

## Отписка от канала
- Бот сам замечает отписку двумя способами: (1) мгновенно — Telegram присылает событие `chat_member`, когда человек выходит из канала; (2) подстраховка — раз в `SUB_WATCH_INTERVAL` сек (по умолчанию 300) бот сверяет подписчиков сам.
- Отписавшемуся приходит сообщение «Вы отписались от канала. Подпишитесь заново и нажмите «Я подписался», чтобы пройти проверку» с кнопками. Пока не подпишется, бот и мини-апп не работают. Сообщение приходит один раз за отписку.
- Когда человек подписывается снова, бот пишет «Подписка подтверждена» с кнопкой «Открыть казино».
- Напоминание получают только те, кто уже был подписан (прошёл проверку) или про кого Telegram прислал событие «вышел из канала». Админы бота не получают.
- Для событий бот ДОЛЖЕН быть администратором канала. В БД добавлена колонка `users.sub_state` (создаётся сама).

## Мини-апп
- Не подписан → на весь экран «НЕОБХОДИМО ПОДПИСАТЬСЯ НА КАНАЛ @casino!» (название берётся из `CHANNEL_LABEL`) с кнопками «Подписаться на канал» / «Я подписался».
- Пока окно открыто, мини-апп сам проверяет подписку каждые 3 сек и при возврате в приложение. Подписался → окно исчезает, мини-апп запускается сам, без нажатий.
- Если игрок отписался во время игры, проверка раз в 30 сек (и любой запрос к серверу) вернёт окно подписки.

# Что изменилось (v19)

## Подписка на канал — почему раньше не просила и что исправлено
- Проверка включается ТОЛЬКО если задана переменная `REQUIRED_CHANNEL` (на Render её не было — `render.yaml` теперь её объявляет). Также подписку не проверяют админы бота (@Richie, @boros, @onewino) и вайтлист — под ними приглашение не появится, тестируйте с обычного аккаунта.
- Раньше при сбое проверки (бот не админ канала, неверный id) бот и сервер молча пускали всех. Теперь пускают только подтверждённых подписчиков; при старте бот проверяет доступ к каналу и пишет админам в личку, если что-то не так.
- Замок стоит на всех кнопках и сообщениях бота (`SubscriptionMiddleware`) и на всех `/api/*` мини-аппа. Открытым остаются только `/start`, «Я подписался», условия использования и оплата.
- Подписан → не просит. Отписался → при следующем действии (бот — сразу, мини-апп — в пределах ~45 сек) снова просит подписаться, играть нельзя, пока не вернётся.

## NFT-подарки
- Подарок, по которому создана заявка на вывод, сразу пропадает из профиля. «Отклонить» — подарок возвращается в профиль (игроку приходит сообщение), «Выдал» — подарок списан окончательно.
- Заявка приходит админам в бот: пользователь, @username, ID, подарок, № заявки + кнопки «✅ Выдал подарок» / «❌ Отклонить».
- Профиль обновляется сразу после выигрыша подарка из кейса; ответы API больше не кэшируются WebView.
- Админы бота проходят вывод подарка без условия «депозит 1000★ + 1 час» (для остальных условие прежнее).

# Что изменилось

## Кейсы и NFT-подарки
- Меню «Кейсы» — отдельная вкладка, не смешана с играми. Шансы и цены — в `bot/cases_config.py`.
- Проверка окупаемости: `python bot/cases_config.py`.
- Результат кейса решает сервер (`/api/cases/open`), списание/приз/история — одной транзакцией.
- Профиль: вкладки «NFT-подарки», «Вывод ★», «Промокод». Подарок можно продать (цены из ТЗ) или вывести — заявка приходит всем админам с кнопками «Выдал / Отклонить». Отказ возвращает подарок в профиль.
- Вывод подарка требует те же условия, что и вывод звёзд (депозит от 1000★ + 1 час, либо админ-разблокировка).

## Upgrade
- Стрелка теперь крутится только вперёд и останавливается точно на ролле сервера. Раньше её каждый раз сбрасывали в 0 через CSS-transition — отсюда «один раз нормально, потом на миллиметр».
- Шансы на экране брались из старой таблицы (30/20/15/7/5%), а сервер считал по другой (50/35/25/15/10%). Теперь экран берёт шансы с сервера.

## Админ-панель (бот, /admin)
- 📊 Статистика: игроки, деньги, выводы, игры, кейсы, подарки.
- 🛠 Техработы: включить/выключить одной кнопкой. Заходят только @Richie и @Boros (список `MAINTENANCE_WHITELIST` в `bot/settings.py`), остальные видят заслонку. Проверка и в мини-аппе, и на сервере (`/api/*` отвечает 503).

## Подписка на канал
- `/start` → «👋 Добро пожаловать! Подпишись на канал👇» → «Я подписался». Та же проверка стоит в мини-аппе и на сервере. Включается переменной `REQUIRED_CHANNEL`.

## Дизайн
- Новая палитра и шрифты, меню из 5 вкладок. Исходник интерфейса: `webapp/src/template.html`, сборка: `python webapp/src/build.py` → `webapp/index.html`.

## Фото в приветствии бота
- К сообщениям «Добро пожаловать! Подпишись на канал» и к главному приветствию прикрепляется фото `bot/assets/welcome.png` (замените файл — поменяется картинка). Текст — подпись к фото.
- После первой отправки бот запоминает file_id и больше не заливает файл. Нет файла или Telegram отклонил фото — уходит обычный текст.
- Для сообщений-фото `edit_text` теперь безопасно удаляет фото и присылает текстовое сообщение, поэтому кнопки меню работают как раньше.

## Загрузочный экран
- Анимация загрузки — Plush Pepe (`webapp/src/blobs/loading_tgs.txt` = `Plush_Pepe.tgs`). Чтобы поменять снова — подставить новый .tgs (base64) в этот блоб и запустить `python webapp/src/build.py`.

## Версия Python
- Добавлен `.python-version` (3.11.9): Render берёт версию Python из этого файла. Без него новые сервисы получают 3.14, на которой `psycopg2-binary==2.9.9` может не собраться.
- В `render.yaml` версия Python теперь задана переменной `PYTHON_VERSION=3.11.9` (документированный способ, имеет приоритет над файлом).

## Сборка на Render (ошибка pydantic-core / maturin / Rust)
- Причина: Render брал Python 3.14, а старые пины (aiogram 3.13.1, pydantic 2.9.2, aiohttp 3.10.10, psycopg2-binary 2.9.9) не имеют готовых сборок под 3.13+ и пытались компилироваться.
- `requirements.txt` переписан на диапазоны версий (aiogram 3.31+, aiohttp 3.13+, psycopg2-binary 2.9.11+): ставится из готовых сборок на Python 3.11, 3.12, 3.13 и 3.14. Версия Python на хостинге больше не критична.
- `/` и `/health` в API теперь async-обработчики (убрано предупреждение aiohttp).

## Адрес мини-аппа, порт, keep-alive
- Кнопка «Открыть казино» вела на старый сервис `onewin-bot-5x1w.onrender.com` (страница «service has been suspended»). Теперь адрес берётся из `WEBAPP_URL`, а если он не задан — автоматически из `RENDER_EXTERNAL_URL` (адрес самого сервиса, его подставляет Render).
- `bot/main.py`: порт берётся из `PORT` (раньше жёстко 8080 — из-за этого Render «переопределял порт» и перезапускал деплой, а два экземпляра бота на секунду вместе опрашивали Telegram → `TelegramConflictError`). Keep-alive теперь пингует собственный `/health`, а не старый сервис и не 8-МБ страницу.
- `HEAD /` отвечает 200 (раньше 405 — на это ругались проверки и пингеры).

## Техработы: доступ только для @Richie и @Boros
- Раньше во время техработ в мини-апп проходили ещё и все админы бота (в т.ч. @onewino), а если `MAINTENANCE_WHITELIST` не был задан на хостинге, вайтлистом становился весь список админов.
- Теперь обход техработ — только `MAINTENANCE_WHITELIST = ["Richie", "Boros"]`, зашит в `bot/settings.py` (env-переменная больше не используется). Остальные, включая других админов, видят экран «Идут технические работы. Скоро откроемся!», а сервер отвечает 503 на все `/api/*` (игры, кейсы, профиль).
- Обход проверки подписки на канал по-прежнему у вайтлиста и админов.
- Чтобы изменить список — правьте `MAINTENANCE_WHITELIST` в `bot/settings.py`.
